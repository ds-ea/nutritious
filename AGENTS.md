# Nutritious — agent guide

Nx monorepo for a nutrition-study platform: a Capacitor mobile app for study participants, a NestJS
API, and a Refine admin panel. This file is the canonical context for AI tooling; `CLAUDE.md` points
here.

## Scope

| Path | What | In scope |
|---|---|---|
| `apps/app` | Ionic/Angular 19 participant app, shipped to iOS + Android via Capacitor | **yes** |
| `apps/server` | NestJS 11 + Fastify API, Prisma over MongoDB | **yes** |
| `libs/core` | Shared types, `Sanitize.*`, study helpers, Prisma schema | **yes** |
| `libs/api-client` | Thin typed API client | **yes** |
| `apps/admin` | Refine/Remix admin panel | no — being addressed separately |
| `apps/server-e2e` | Jest e2e harness, currently a stub | no |
| `apps/nutritious-api-php` | Dead legacy PHP API | no — do not touch |

Do not make changes in the out-of-scope areas unless asked directly.

## Before anything works

1. `pnpm install` — see the corepack note below if this fails with "Cannot find matching keyid".
2. **`nx run core:prisma:generate`** — the Prisma client is not checked in and is not generated by a
   postinstall hook. Until it exists, every server test and build fails at the `@prisma/client`
   import in `libs/core/src/lib/data/sanitize.ts`.
3. Use **Node 22** (see `.nvmrc`). This is not a preference — on **Node 24+ the API does not run
   at all**: `jsonwebtoken` pulls in `buffer-equal-constant-time`, which reads `SlowBuffer` from
   the `buffer` module, and `SlowBuffer` was removed in Node 24. Anything touching
   `@nestjs/jwt` — every authenticated request, and the auth specs — dies with
   `TypeError: Cannot read properties of undefined (reading 'prototype')`. Angular 19 also only
   supports up to Node 22. Pin the runtime in deploys, not just locally.

### pnpm and corepack

`package.json` pins `packageManager`, and **pnpm 10+ provisions that exact version itself** — no
corepack required. Install pnpm once (`brew install pnpm`) and the pin does the rest.

Do not enable corepack for this repo. Under nvm, corepack installs a `pnpm` shim into each Node
version's `bin`, which shadows the real pnpm; Node 22.18 bundles corepack 0.28.2, whose pinned npm
registry signing key has since been rotated, so every `pnpm` command dies with
`Error: Cannot find matching keyid`. If you hit that, the fix is:

```
corepack disable
```

which removes the shim and lets the standalone pnpm take over. It has to be re-run for each Node
version nvm installs.

## Commands

Prefer the root `package.json` scripts. The underlying Nx targets:

| Task | Command |
|---|---|
| Serve API | `nx serve server` |
| Serve app in browser | `nx serve app` |
| Test one project | `nx test app` \| `nx test server` \| `nx test core` |
| Test everything | `nx run-many -t test` |
| Lint | `nx run-many -t lint` |
| Build app (web) | `nx build app` |
| Build app (mobile payload) | `nx run app:build:production-mobile` |
| Build API | `nx build server` |
| Prisma client | `nx run core:prisma:generate` |
| Prisma schema push | `nx run core:prisma:push` |
| Sync native projects | `nx run app:sync` |
| Bump build number | `nx run app:version-bump` |

If the Nx daemon cannot start (sandboxed environments cannot open its unix socket, and the failure
reads "Failed to start plugin worker"), run Jest directly — it needs no daemon:

```
node node_modules/jest/bin/jest.js --config apps/app/jest.config.ts --rootDir apps/app --passWithNoTests
```

## Tests

212 tests over four projects. They exist to make a dependency or SDK upgrade survivable, so they
concentrate on logic that fails silently rather than loudly:

| Where | What it protects |
|---|---|
| `apps/app/.../dashboard/process-schedule.spec.ts` | The scheduling engine — which slots a participant sees as todo / upcoming / missed / overdue on a given day |
| `apps/app/.../registration/signup-code.spec.ts` | QR signup payload parsing, both the legacy and obfuscated formats |
| `apps/app/.../study/study.service.spec.ts` | The offline response queue — the one place a regression destroys unrecoverable data |
| `apps/app/.../core/api.service.spec.ts` | Base-URL assembly, bearer token, 401 → session-expired |
| `apps/app/.../core/core.service.spec.ts` | Session persistence through `@capacitor/preferences` |
| `apps/app/.../app.module.spec.ts` | DI smoke — fails loudly when an Ionic/Angular upgrade changes provider resolution |
| `apps/server/.../auth/auth.service.spec.ts` | Legacy PHP-era bcrypt hashes **and** the argon2 path |
| `apps/server/.../auth/auth.guard.spec.ts` | `@Public()` / `@ParticipantAccess()` / user-only access rules |
| `apps/server/.../study/study.service.spec.ts` | Signup gating and the prepared-schedule payload the app caches |
| `libs/core/.../sanitize.spec.ts` | That participant-facing payloads never carry a password |
| `libs/core/.../time-helpers.spec.ts`, `xor-encrypt-decrypt.spec.ts` | Time formatting and QR obfuscation |

`libs/api-client` has no tests: it is only consumed by `apps/admin`, which is out of scope.

Notes for writing more:

- App specs run under jsdom via `jest-preset-angular`. Ionic and Stencil publish untranspiled ESM
  in `.js` files, so `apps/app/jest.config.ts` routes them through esbuild via
  `globals.ngJest.processWithEsbuild`. Without that, anything importing `@ionic/angular` fails with
  "Cannot use import statement outside a module".
- `apps/app` cannot use the `@nutritious/core` path alias: `apps/app/tsconfig.json` overrides
  `baseUrl`, which breaks the `paths` mapping from `tsconfig.base.json`. Relative imports into
  `libs/core/src` are the working convention there, even though `@nx/enforce-module-boundaries`
  flags them.
- Prefer constructing services directly with stubs over `TestBed` — most of these specs do.
- Server specs mock `PrismaService`; there is no test database, by design.


## Code style

Match the surrounding code; it is deliberate and consistent, and Prettier is **not** run over the
source tree.

- **Tabs** for indentation (`.editorconfig`), single quotes (`.prettierrc`).
- Type annotations have no space before the colon: `private api:ApiService`, `public url:string | undefined`.
- Spaces inside parens and brackets: `if( !slot )`, `entries.map( entry => ... )`, `[ 'a', 'b' ]`.
- Single-statement `if` bodies are written without braces on the following line.
- Two blank lines between class members in the older files; follow whatever the file already does.

## Landmines

These are not inferable from the code and have each cost a release before.

**App config is injected at build time, not read at runtime.** `apps/app/webpack.config.js` copies
every `NX_*` environment variable into `process.env` via webpack `DefinePlugin`, and
`apps/app/src/app/core/config.service.ts` reads them from there. The full set is declared in
`apps/app/src/types.d.ts`:

```
NX_API_URL  NX_QR_CODE_HASH  NX_DEPLOYMENT_ENV  NX_PROJECT_NAME
NX_PRIVACY_URL  NX_SUPPORT_URL  NX_APP_VERSION  NX_APP_BUILD
```

If `NX_API_URL` is unset at build time the build still succeeds and ships an app that cannot reach
the API — the build warns about this, but does not fail. Always verify the injected values in the
emitted bundle before releasing.

`NX_APP_VERSION` and `NX_APP_BUILD` are the exception — they come from
`apps/app/.buildversion.json`, never from the environment. Setting either as an env var **fails
the build**:

```
Refusing to build: NX_APP_VERSION set in the environment. Remove it from .env, or set
NX_APP_ALLOW_ENV_VERSION=1 to build with the environment value deliberately.
```

Nx auto-loads `.env` into the task environment, so a stale `NX_APP_VERSION` there would otherwise
silently label a build with a version that never corresponded to the code in it. Set
`NX_APP_ALLOW_ENV_VERSION` to a truthy value to override on purpose; `''`, `0`, `false`, `no` and
`off` all count as not set. The value is fixed at **web build** time, so bumping the build afterwards for a
native-only change deliberately leaves the in-app version showing what the JS was built from.

**The iOS bundle id differs from the Capacitor appId on purpose.**

| | value |
|---|---|
| Capacitor `appId` | `de.dife.foodapp` |
| Android `applicationId` | `de.dife.foodapp` |
| Android `namespace` | `net.dsea.foodstudyapp` |
| iOS `PRODUCT_BUNDLE_IDENTIFIER` | `com.ipsy.foodapp` |

The App Store record uses `com.ipsy.foodapp`. Never "fix" this mismatch, and re-check it after any
`cap migrate` or `cap sync`.

**Generated vs hand-edited native files.** `apps/app/android/capacitor.settings.gradle`, the iOS
`Podfile` and `Podfile.lock` are regenerated by `cap sync` and contain pnpm content-hashed paths
(`node_modules/.pnpm/@capacitor+ios@<version>_.../`) that change on every dependency bump — never
hand-edit them. `apps/app/android/variables.gradle`, `android/build.gradle`, `android/app/build.gradle`
and the Xcode project *are* hand-edited.

**`libs/api-client` does not build.** `libs/core/src/index.ts` re-exports its types with
`export type * from './types'`, and the rollup build drops those re-exports — the emitted
`dist/libs/core/index.cjs.d.ts` contains none of them, so `api-client:build` fails with
"Module '@nutritious/core' has no exported member 'AuthLoginResponse'". Nx's cache hid this for a
long time. `apps/app` does not import api-client at all, so it was removed from the app's
`implicitDependencies`; only `apps/admin` consumes it, so the fix belongs with the admin work.
Do not "fix" it by changing `export type *` to `export *` — the type modules import from
`@prisma/client`, and a value re-export would drag Prisma into the app bundle.

**The Capacitor Nx targets call the CLI directly, on purpose.** `apps/app`'s `cap` / `sync` /
`copy` / `open` / `run` / `update` / `add` targets use `nx:run-commands` with
`cwd: apps/app`, not the `@nxext/capacitor` executors. `@nxext/capacitor@19.x` reads
`context.workspace.projects`, an API Nx 21 removed, so every one of those executors throws
"Cannot read properties of undefined (reading 'projects')". `.npmrc` sets
`strict-peer-dependencies=false`, so its `nx: ^19.0.0` peer went unsatisfied silently and this
stayed hidden from the Nx 21 upgrade until someone next ran a native build. A matching
`@nxext/capacitor@21.0.0` exists if you would rather go back to the plugin, but the CLI is the
real interface and calling it directly removes the version coupling entirely.

**Building the server needs the admin app built.** `apps/server/project.json` copies `apps/admin/dist`
in as a build asset, so `nx build server` fails on a clean checkout until admin has been built once,
even though admin is out of scope here.

**Four dependencies are pinned for non-obvious reasons.**

- `fastify` is pinned to an **exact** version, not a range. `@nestjs/platform-fastify` pins its own
  fastify exactly, so a caret range here resolves to a *second* copy and `app.register(fastifyHelmet)`
  in `apps/server/src/main.ts` stops typechecking with an inscrutable "Target signature provides too
  few arguments". Re-check this pin against `@nestjs/platform-fastify`'s dependency after any Nest
  upgrade.
- `prisma` and `@prisma/client` are pinned to the **same exact version in both the root
  `package.json` and `libs/core/package.json`**. `libs/core` is a pnpm workspace package, so its own
  declaration resolves independently: if the two disagree, pnpm links two copies of
  `@prisma/client`, and `nx run core:prisma:generate` — which runs with `cwd=libs/core` — populates
  the copy that `apps/server` does *not* resolve. The server then fails to typecheck with
  "Module '@prisma/client' has no exported member 'Participant'" while the tests still pass. Change
  all four declarations together or none.
- `cordova-sqlite-storage-dependencies` is declared even though it is only a transitive
  dependency of `cordova-sqlite-storage`. Capacitor's CLI resolves Cordova plugin dependencies
  from the workspace root, and pnpm does not hoist transitives there, so `cap sync` fails with
  "Can't resolve module cordova-sqlite-storage-dependencies".
- `@ionic/storage` is declared even though `@ionic/storage-angular` already depends on it, because
  `apps/app/src/app/app.module.ts` imports `Drivers` from it directly and
  `@ionic/storage-angular` does not re-export that. Same reason `webpack` is declared: it is
  `require`d directly by `apps/app/webpack.config.js`. Under pnpm's strict linking an undeclared
  direct import only resolves by accident.

**Secrets.** `.env` and `.env.*` are gitignored and blocked from reading. `.env-example` documents
only the server-side variables and is missing the whole `NX_*` set above.

## Server conventions

- Controllers must return `Sanitize.*` output (`libs/core/src/lib/data/sanitize.ts`), never a raw
  Prisma model. Participant-facing payloads otherwise leak `password` and internal state.
- Access control is declarative, enforced by `AuthGuard` (`apps/server/src/app/auth/auth.guard.ts`):
  - `@Public()` — no token required.
  - `@ParticipantAccess()` — a participant token is accepted; without it the route is user-only.
  - Neither decorator means **user-level access only**; a participant token gets a 403.
- Prisma targets **MongoDB**. Transactions need a replica set, so unit tests mock `PrismaService`
  rather than hitting a database.
